# Тариф за м³ для вывоза с земли

## Данные и расчёт

- Касса M «Объект» сохраняет количество ходок / бункеров.
- Q «Объём, м³» — общий числовой объём; R «Единица тарифа» — `м³`;
  S «Тариф на дату вывоза» — сохранённая цена за куб.
- Для нового `/h` без наличных выручка = округлённое до копеек Q × S.
  Тариф фиксируется в момент первой успешной записи в кассу. Ретрай
  проверяет метку отчёта до чтения тарифов и не меняет уже записанную строку.
- Тариф читается из новых колонок K «Единица тарифа» и L «Тариф за м³»
  вкладки «Бункеры». E/F остаются для прежнего расчёта, исторические формулы не меняются.
- Бункеры по-прежнему оплачиваются по количеству с коэффициентами; их тарифы не менялись.
- «Частник» с наличными сохраняет фактически полученную сумму по прежней схеме.
- Счёт по новой работе содержит м³ и зафиксированный тариф. Старые работы без
  `billing_unit` остаются в прежних единицах. Сегменты с разными единицами не объединяются.
- Отсутствующий/нулевой тариф оставляет отчёт в очереди, ошибка видна администратору.
  Счёт при отсутствии объёма/тарифа или несовпадении суммы не формируется.
- Колонка L «Сальдо» кассы не изменяется.

Для ручной новой записи заполняются Q/R/S; формула O в подготовленных свободных
строках поддерживает обе схемы и показывает ошибку при незаполненных Q/S для м³.
Бот заполняет эти поля автоматически. Изменение справочника не пересчитывает
выручку уже записанного вывоза с земли. Изменять S старых строк вручную не следует.

## Первичное заполнение 17.10.2026

Использована действующая «Цена 2», если положительная, иначе «Цена».
По согласованию с пользователем выбирается точное деление на 30 или 36;
при двух целых результатах — 30. Явная формула на 36 имеет приоритет.
Если ни одно деление не даёт целого тарифа, поле оставляется пустым.

## Развёртывание

1. Миграция панели `2026_10_17_000023_add_work_billing_tariff` или Alembic `023`
   добавляет `works.billing_unit` и `works.tariff` (обе миграции проверяют наличие полей).
2. Обновить tbank-service вместе с миграцией: чтение новых полей и счета в м³.
3. Обновить map-service (проверка соответствия объёма) и панель (поля в списке работ).
4. Обновить bot-reports **вместе с config/schema.json** и перезапустить службу.
   До этого отчёты продолжают записываться по старой схеме.

Колонки Google-таблицы уже подготовлены. Повторная подготовка:
`python configure_volume_billing.py` — просмотр; `--apply` — применение.
Скрипт не перезаписывает заполненные новые тарифы. Перед записью сохраняет
резервную копию формул двух листов в `data/private-state/volume-billing-backups/`
на сервере, файл 0600; резервные копии не добавляются в Git.

## Проверка

Реальные формулы Google Sheets проверены на временной вкладке (после проверки
удалена): 30/36/66 м³ × 1200 = 36000/43200/79200; 1,5 бункера × 9480 = 14220.
Сверка с резервной копией подтвердила неизменность старых цен, исторических
строк кассы и всех формул «Сальдо».

Локально прошли 48 тестов бота, 26 проверок биллинга/синхронизации/работ,
2 PHP-теста (9 assertions), PHP-интеграция API и сборка Node 22.
Расширенный запуск `tests/invoice` дополнительно выявил три падения в
неизменённых `test_splitter` (2) и `test_window` (1); эти участки в задаче не менялись.
Код и миграции на рабочие сервисы в ходе этой задачи не устанавливались.
