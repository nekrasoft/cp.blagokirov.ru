# Надёжная отправка отчётов о вывозе

## Порядок выкладки

1. Обновить tbank-service: чтение таблицы должно удалять служебные метки доставки из примечаний к счетам.
2. Обновить админку и выполнить `php artisan migrate --force`. Миграции `000020` и `000021` добавляют идентификатор отправки, очередь и индексы. Они совместимы с предварительным созданием этих колонок API карты.
3. Обновить map-service (`api.php` и `pickup_delivery.php`).
4. Обновить bot-reports и выполнить `service bot-reports restart`. Фоновый обработчик запускается вместе с `run.py`, отдельная служба не нужна.

Перед обновлением бота API карты обязательно должно поддерживать очередь. Иначе бот сохранит черновик и сообщит, что подтверждение не получено.

## Поведение

Идентификатор отправки и снимок отчёта сохраняются до сетевого запроса. Повтор использует те же данные, талоны и дату. API возвращает прежний отчёт по уникальному идентификатору; новая заявка по тому же бункеру остаётся активной. После неопределённого результата редактирование и отмена отправленного снимка закрыты до повторного подтверждения. Явный отказ API разрешает исправить отчёт.

Строка Google Sheets сохраняется в той же транзакции, что и вывоз. Состояния в админке: «В очереди», «Отправляется», «Ожидает повторной доставки», «Доставлен». Есть фильтр «Ожидают записи в таблицу».

Файловая блокировка в закрытом каталоге состояния допускает один обработчик на установку bot-reports, в том числе при одновременном запуске Telegram и MAX. Обработчик забирает одну задачу с блокировкой строки и арендой на 10 минут. Ошибка откладывает следующую попытку на минуту. После аварийного завершения аренда истекает, и задачу забирает следующий процесс. Неверный или устаревший токен подтверждения не меняет состояние задачи.

Перед добавлением строки обработчик проверяет метку `[ВЫВОЗ:<идентификатор>]` в колонке «Примечание». При потере ответа повтор находит уже добавленную строку. Вставка строки, данные, метка и копирование формул выполняются одним атомарным запросом Google Sheets. Коэффициент передаётся числом, а дата — как дата, без автоматического распознавания текста. Метку нельзя удалять вручную до завершения доставки. tbank-service удаляет её при чтении примечания для счёта.

## Наблюдение

- Админка → «Отчёты о вывозе» → «Ожидают записи в таблицу».
- `journalctl -u bot-reports -f` — текущие логи, включая ошибки доставки с ID отчёта.
- `journalctl -u bot-reports --since '1 hour ago'` — последние попытки.

Существующие отчёты без сохранённой строки имеют пустое состояние доставки. Они не отправляются задним числом автоматически: сначала нужно проверить, отсутствуют ли они в таблице.

Очередь восстанавливается автоматически, когда бот снова работает. Если служба остановлена, задачи остаются в базе. Проверки с имитацией сбоев не заменяют проверку в рабочей таблице после выкладки.
